## 1. なぜ順位だけでは精度がわからないか

蒲田の公開UR4建物・12経路では、街区代表点、駅代表点、バージョン未固定のValhallaデモ道路グラフで徒歩距離を計算してきた。参考1位が安定しても誤順位になる事例があった。建物構造RC/SRCを重ねた同一集合の順位改善は、広告と候補が同じUR公式出典に由来するため外部検証ではない。

**改善したいのは、不十分な距離や同じ出典を「独立で精度の高い物件特定の証拠」と誤認しないこと**。正解率を示す新しい独立評価集合がない状態で、点数を高く見せる調整は実施しない。

## 2. 今回の判定保留ゲート

ひとつの徒歩経路が評価に使用できる品質として認められるための研究用条件：

1. 起点が**公表済みの建物入口**で、位置の一次資料・独立照合元URLが記録されていること。
2. 終点が鉄道駅の**特定の出入口**で、駅代表点ではなく現況・座標出典が確認されていること。
3. 歩行ネットワークデータの版・参照先・移動プロフィール（歩行）・計測日が保存されていること。
4. 起終点をネットワークに結びつけた際の道路吸着量が暫定レビュー閾値25m以下であること。これは精度保証の閾値ではない。
5. 経路データが失われたり、駅の物理的同一性を確認できなかったりした場合、未確認のままにすること。
6. 1候補につき異なる物理目的地の経路が2件以上、かつ比較対象すべてで品質条件を満たす場合のみ「**独立評価を開始できる状態**」とみなす。ただし、建物同定は**その時点でも未検証**。

具体的な実行データにはこれらの品質メタデータがないため、どんなに参考順位が安定していても `gate=withhold_identity_decision` を出す。建物を自動排除することもない。

※入力メタデータの `independently_surveyed=true` はソース提供側の**申告値**であり、第三者が真に測量したという保証ではない。外部品質監査の通過を別工程で必須とする。

## 3. 現在の12経路の現況

- **12/12件**が駅出口・建物入口の独立座標やグラフ版を証明できないため、経路品質確認は0/12。
- 蒲田駅前ハイツ（起点吸着37m）3経路、蒲田本町一丁目（起点吸着54m）3経路の合計**6/12件**で道路への端点吸着が暫定25mを超えた。
- 端点吸着が閾値以内の6経路も、駅出口の位置が公的に独立検証されたわけではないので品質合格に昇格しない。
- 既存の参考順位／構造による並べ替えは研究のために表示を残すが、UIで「品質確認済み経路0件」「判定保留」を表示する。
- 12経路は4建物×3駅。各広告で2駅を使う場合は8経路を比較する。その画面でも `0/8` 等を正しく表示する。

## 4. 別地域の公的な歩行空間データ

[ほこナビDPのオープンデータカタログ](https://ckan.hokonavi.go.jp/dataset/nwd_akabane_station)に、**国土交通省の赤羽駅周辺の歩行空間ネットワークデータ**を確認した。データセット上の更新日：**2026-03-19**。ライセンスは**公共データ利用規約第1.0版**。リソースにはノードとリンクのCSV・GeoJSONがある。

| リソース | 形式 | カタログ上のファイルサイズ |
| --- | --- | ---: |
| link.geojson | GeoJSON | 3,739,486 bytes |
| node.geojson | GeoJSON | 1,828,804 bytes |
| link.csv | CSV | 659,031 bytes |
| node.csv | CSV | 444,483 bytes |

カタログの [CKAN API](https://ckan.hokonavi.go.jp/api/3/action/package_show?id=nwd_akabane_station) は2026-10-20に200応答で確認。**一方、実データダウンロードは今回の取得環境でブロックされており、ファイル内容・地物の収録範囲・駅出入口の有無は読めていない。** したがって収録されていると推定して道路・出入口座標を追加したり、別地域の経路精度向上を宣言したりしない。JSONにはURI、データサイズ、リソースID、未取得状態を正確に残してある。新しい地域の公表住宅群を評価する条件として、実ファイルの検証が別途必要。

公式カタログはデータの整備仕様とライセンスが明確なのでR07/R08の次の調査対象として有望だが、MLITのメタデータ発見自体は**R06/R07/R08の完了条件ではない**。

## 5. 検証方法と次工程

- Node回帰テストは正常データ、品質メタデータ欠損、端点スナップ>25m、グラフ未固定、同一URLの出典混同、欠測、広告の同源メタデータに対し、誤った正解認定を出さないことを検査する。
- 次は赤羽のノード・リンクファイルの**再利用権・実ファイルの読込み・ジオメトリ範囲・ノードID重複・リンク参照・歩行者用リンクが駅出口へ接続されるか**を順に確認する。中身が確認できるまではここまでを未完了とする。
- 公開サイトに載る新しいUR集合を研究用に選ぶとしても、既存蒲田4件で重みを追加調整したデータを「独立ブラインド評価」とは呼ばない。
- `quality_provenance`は検証済みの一次資料に結びつける**将来のアダプタ入力形式**であり、既存データに根拠のないtrueを付与しない。
