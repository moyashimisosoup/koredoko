# APP-023「これどこ」｜OpenPOI APIの施設照合導入 CHECKPOINT（2026-10-22 JST）

**方針：** 地図の中央地点を推定するための「登録済み物件7棟」の研究から、**未知の戸建・マンション・土地でも広告の施設条件を区域推定へ渡す**主経路を優先。OpenPOIは「施設名と公開座標の照合」だけの責務とし、物件の特定や道路距離計算には使用しない。

## 正式API仕様の確認（2026-10-22）

- [OpenPOI API ドキュメント](https://docs.openpoiapi.com/)、[出典・ライセンス](https://openpoiapi.com/attribution.html)
- `GET https://api.openpoiapi.com/v1/search?q=<施設名>&center=<経度,緯度>&radius=6000&limit=15`
- 認証不要、CORS全オリジン対応。全国約300万件のPOI。Overture Maps、食品営業許可オープンデータ、国土数値情報の駅・学校・公共施設を含む。
- `/v1/search` は複数検索語をOR検索するため、**施設名を1件ずつ検索**し、返却先頭結果を機械的に採用しない。`/v1/suggest` は将来の手動候補選択UI向け。
- `level` の小さい座標は町丁目・市区町村相当であり、入口ではない。施設が消えていたり数百km位置ずれ、複数出典で重複・同名施設が多数ある可能性を考慮。
- 画面に出す際はOpenPOIの出典URLを表示。結果の`source`, `licenses`, `attributions`を内部の引用根拠付きオブジェクトに保持。再配布・加工公開時のライセンスはソース別の追加条件を確認する。全国版の公開データキャッシュは今回作成しない。
- APIへのGETは公開施設名のみ。**広告全文、所在地の一部、個人住宅の住所、物件IDを送らない**。検索範囲の`center`は既存の公開施設・町丁目代表点であり、ユーザーのGPS・現在地ではない。
- サービスの`429`・CORS・通信失敗時は処理を中断せず、参照できた他施設の条件で区域を求める。地域の手がかりがない場合は全国からの同名自動照合をしない。

### 現時点の検証境界

- **新しいモジュールのNodeモック回帰と既存回帰はGitHub Actionsで成功**。`https://api.openpoiapi.com`への本番レスポンス取得・現実の施設座標との照合、iPhone Safari操作は未検収。モック合格を実ネットワークAPI動作確認とは呼ばない。
- **全国任意施設へ完全対応したわけではない**。現時点の地域文脈はひばりヶ丘の町丁目と登録施設。地域が未確定の「知らない施設A」だけではAPIへ問い合わせず、少なくとも公開の町名や既知施設が必要。全国の住所文字列をジオコーディングして探索範囲に変換する処理は別工程。
- 物件名の識別や個別建物の特定は主機能に戻さない。Web地図は現在相対位置図であり、等距離圏・実歩行範囲との交差は今後の追加工程。
- 現在のGitHub Pagesサイトは`preview/app023-iphone-20261022`ブランチ由来。**この変更は開発ブランチのみで、公開サイトにはまだ反映していない**。プレビューブランチの更新・Pages再公開・Safari検収は別工程。
- P0〜P5のマイルストーンは**P0のみ完了（1/6）**のまま。位置推定の独立coverage（正解を区域が含む率）や縮小面積効果は未測定。
